# Named Tricks: Move, Signing Context and Counter-Cases

> Loaded when: Choosing or reviewing a specific code, API, control-flow, error-handling, type or build/CI pattern.

Matklad structures his tactical and mid-scale architecture knowledge as named tricks: a label pointing to the code shape, the context where it pays off (`Signed when`), and the context where it fails or was reversed in his own work (`Wrong when`). Tag legend: `[C]` = contemporaneous in commits/PRs/docs at decision time; `[R]` = later retelling or essay.

## Control flow, effects and state

| Trick (tag) | Move | Signed when | Wrong when / counter-case |
|---|---|---|---|
| **Push Ifs Up** `[C]` | Move preconditions and `if` branches up to the caller; centralize branching in one top-level dispatcher and keep callees straight-line, encoding preconditions in types. | Stateful or side-effecting code; preconditions that become viral and collapse into fewer checks at the top because the caller has more context. | Do not extract single-use helper functions just to separate branches (`STYLE:1041`). |
| **Push Fors Down** `[R]` | Make a batch of items (`&[Item]`) the base case rather than a single item, amortizing `O(1)` control-plane decisions over `O(N)` data-plane work. | Hot paths where volume makes the path hot and per-item branching dominates. | Cold or script-level code where batching adds friction for no gain. |
| **Scalar Select Anti-Pattern / Always Be Batching** `[C]` | When an event loop is driven by external I/O, pull *all* ready events into a batch, then prioritize (writes > reads > accepts), back-pressure, eliminate and coalesce. | External I/O streams where multiple events arrive while one is processed ("I had to refactor this loop later, every time"). | Under low load, batches are singletons, which the batch API handles naturally. |
| **Enum of Arrays (`AoE => EoA`)** `[R]` | Replace an array of tagged enums with a single batch tag over homogeneous arrays. | Batch processing where the CPU branches on the tag once per batch instead of per element. | Heterogeneous single-item APIs where batching does not apply. |
| **Dissolving Enum** `[C/R]` | Delete an enum that exists only to record a branch in a producer so a consumer can `match` on it immediately; pull both branches up to the caller. | The same `if` condition is triplicated across producer, enum definition and consumer (`reified control flow`). | When the data structure is genuinely stored, serialized or inspected across decoupled stages. |
| **Prefer Separate Functions Over Bool/Option Parameters ("false sharing")** `[C]` | Split `fn foo(flag: bool)` into `foo_a()` and `foo_b()` when callers always pass literal `true`/`false`/`Some`/`None`. | Call sites pass literals and the function branches internally on the parameter. | Kaminski narrows: matters mainly on a system boundary; inside a module it is a minor control-flow cleanup. |
| **Sans-IO** `[C]` | Extract protocol state machines, parsers and algorithms into pure state transitions driven by the caller, with zero I/O calls inside. | I/O-heavy components (`MessageBus`, `ReceiveBuffer`, `FaultDetector`, IDE core) that need batching, prioritization or deterministic fuzzing. | None stated for core logic; exchanges a bit more caller plumbing for determinism and error elimination. |
| **Call-Site Dependency Injection (CSDI)** `[C]` | Pass context, config, allocators or parent IDs as arguments to each method call (`&Context`) instead of storing them as fields at construction. | Avoiding lifetime/borrow-checker contagion in Rust, or allowing different configs per call on the same state. | Fails when `Drop` needs the dependency (e.g. an allocator to free memory on drop); in two cases (`ra #2325` parent IDs, `tb 3fab9811f` `Tracer`) threading context everywhere felt like busywork and was reverted ([fork F10](limits.md#forks-and-reversals)). |
| **Withhold the Capability** `[R]` | Pass an allocator or `Io` handle to `init()`, and omit it from the event-loop / transaction step signature so allocation or syscalls are impossible there. | Enforcing "no allocation after startup" or hermetic evaluation (e.g. `comptime`, config evaluation) via the type system. | Escape hatches via thread-locals take years to refactor away (`rustc` parser session). |
| **Hard Mode / Static Allocation** `[R]` | Allow only `main` to request OS resources; pre-allocate all memory at startup from worst-case CLI bounds and drop work on overload. | Systems with finite message/batch physics (such as TigerBeetle's 1 MiB messages) where predictable memory ceilings and zero-code backpressure matter. | Fails when input sizes are unbounded (such as compilers, where static allocation "seems impossible"), and does not prevent `ENOSPC` on disk. |
| **Reserve First** `[R]` | Split a fallible mutation into (1) a `reserve` step that allocates all needed capacity without mutating state, and (2) an infallible mutation step. | Data structures where fallible allocation is the only error source and partial mutation would corrupt invariants (credited to Andrew Kelley). | For libraries, leaving allocation to the caller altogether is often simpler. |
| **Interior-Mutability Cache** `[R]` | Keep cached read methods `&self` using internal cell/lock types rather than changing read signatures to `&mut self`. | Preventing `&mut self` from becoming viral and erasing the type-level distinction between reads and writes across the program. | Treat every interior-mutability spot as architecturally salient; for bounded local caches, shared ownership (`Rc`) may beat a global cache. |

## Types, APIs and encapsulation

| Trick (tag) | Move | Signed when | Wrong when / counter-case |
|---|---|---|---|
| **Concrete Abstraction (anti-pattern)** `[C]` | Delete a trait or generic parameter when every call site uses a known concrete type; replace with concrete functions. | `conv.rs`-style internal traits or `AsRef` polymorphism that add lines and compile time without compressing code. | Keep the abstraction when code is genuinely generic over `T`, or when a boundary needs a second implementation (such as a diagnostic sink). |
| **Avoid Monomorphization (`inner` trick)** `[C]` | At crate boundaries, make the public generic function a 1-line wrapper that converts arguments and calls a non-generic `_impl` function; prefer `&dyn Fn` over `impl Fn` on cold paths. | Cross-crate APIs in compiled languages where generics duplicate code generation in every downstream crate. | Ultra-hot inner loops where dynamic dispatch or conversion is measured to dominate. |
| **Binary Privacy** `[C]` | Make *all* fields of a struct `pub` (plain data) or *none* of them `pub` (an ADT guarding an invariant). Never write getters or setters. | Application code inside a repository you control: privacy exists only to keep an invariant local to one module. | SemVer-constrained public libraries, where hiding representation behind a boundary is required ([S3](../SKILL.md#the-six-concept-spine)). |
| **Config-Struct Parameter** `[C]` | Pack many optional or boolean parameters into a `Config` struct passed to the function; do *not* implement `Default` for `Config` and do *not* store it in state. | Functions with frequently changing option sets passed through intermediate layers. | Callers have more context to pick defaults; storing `Config` in state hides per-call variation. |
| **Builder Lite** `[R]` | Instead of a separate `FooBuilder` type, add chaining `with_bar(mut self, ...) -> Self` methods directly onto `Foo` after `Foo::new(...)`. | Rapidly evolving application code where optional overrides (especially in tests) grow over time. | Types where the unconfigured state is invalid and must be unrepresentable in public library APIs. |
| **Functions Over Doer Objects** `[C]` | Expose a free function `do_thing(...)` at the module boundary instead of `ThingDoer::new(...).run()`, keeping the state struct private inside the function. | Outward module APIs where an object is instantiated only to run a single action. | When the object's state is genuinely reused across multiple caller-driven steps. |
| **Newtype Index** `[R]` | Wrap arena/slice integer indices (`u32`) in a distinct newtype per collection (`NodeId`, `Tree`) so indexing array A with index B fails type-checking; define the container (`Tree`) before the element (`Node`). | Codebases with multiple parallel arrays/arenas where raw `usize`/`u32` arguments are hard to read at call sites. | In small hobby programs, arena indices make programming-in-the-small more annoying than pointers. |
| **Typed Key** `[C]` | Attach the value's type `PhantomData<V>` to the key of a heterogeneous map (`Key<V>`). | Extensible plugin architectures where independent modules register options into a shared map whose full schema cannot be known upfront. | When the set of fields is statically known upfront — use an ordinary struct with `serde` instead ([fork F3](limits.md#forks-and-reversals)). |
| **Boundary-Marking Path Types (`AbsPathBuf`, FS witness)** `[C]` | Use distinct types for absolute validated paths vs raw OS strings, and require an existing path as a "file system witness" rather than assuming one global filesystem or `cwd`. | Long-lived server processes handling multiple workspaces where accidental reliance on process `cwd` or non-UTF-8 paths is a bug. | Short-lived single-directory CLI scripts. |

## Errors and diagnostics

| Trick (tag) | Move | Signed when | Wrong when / counter-case |
|---|---|---|---|
| **Diagnostics Factory (Thin Film)** `[R]` | Instead of one giant error enum shared between producer and consumer, give producers a `Diagnostics` sink with one constructor method per error kind (`diag.err_foo(span, x)`), formatting or storing inside the sink. | Compilers, linters and validators where dozens of error variants are emitted in one place and reported at an outer boundary, and callers only care *whether* an error occurred (`bool` / `ErrorGuaranteed`). | In short script-like code, a diagnostics sink adds too much ceremony (`zig-error-context:19-20`). |
| **Error Codes for Control Flow vs Sink for Reporting** `[R]` | Separate errors handled programmatically (a small closed enum of error codes, or `Result<Result<T, Expected>, IoErr>`) from errors presented to a human operator (rendered immediately or sent to a diagnostic sink at the isolation boundary). | Keeping error types small (avoiding "error virality" where one large payload bloats every `Result` return ABI) and decoupling control flow from error messages. | "Midpoint" application error handling remains an open, unsolved tension ([limits](limits.md#boundary-and-gaps)). |
| **Infallible Core: `(T, Vec<Error>)` and `catch_unwind`** `[C]` | Have parsers and analysis passes return a partial/lossless value alongside a list of errors instead of `Result`, and wrap each read-only feature request in `catch_unwind` over an immutable snapshot. | Interactive tools and IDEs where broken input is the norm and availability matters more than aborting on a single feature bug. | Systems like financial ledgers (TigerBeetle) where correctness beats availability and any unexpected state must crash immediately. |

## Modules, crates and boundaries

| Trick (tag) | Move | Signed when | Wrong when / counter-case |
|---|---|---|---|
| **`ARCHITECTURE.md` and Codemap** `[C]` | Write a short `ARCHITECTURE.md` with a bird's-eye codemap ("a map of a country, not an atlas of its states"), explicit **Architecture Invariants** (mostly absences) and marked **API Boundaries**. Name files/symbols as plain text instead of hyperlinks, and record only what rarely changes (revisit twice a year). | Projects between 10k and 200k lines of code, where finding *where* to change code takes 10× longer than writing the patch. | Hyperlinks rot on every file move; trying to keep docs synchronized line-by-line with code fails. |
| **Flat Workspace (`crates/*`, `libs/`)** `[R]` | Place all internal crates in a flat `crates/<name>` directory (folder name = crate name) under a virtual manifest, and put publishable crates with zero internal dependencies in `libs/`. | Workspaces from 10k to 1M lines of code: "there are no perfect hierarchies", and a flat list makes splitting, merging or checking `libs/` independence trivial. | Past ~1M lines of code a nested hierarchy scales better. |
| **Kitchen Sink (`shortcuts`, `stdx`)** `[C/R]` | Create an explicit module or leaf crate for glue and helpers that belong to no single domain module (`Models` vs `Views`). | When a crisp classification of primary modules already exists and forcing a cross-cutting helper into one of them would blur "who knows whom". | Without a solid primary design first, a kitchen sink degenerates into a dumping-ground `utils` folder. |
| **Serialization at the Leaf vs Raw Checksummed Bytes** `[C/R]` | When you do *not* control the other side (LSP, external JSON/IPC), keep `serde` and wire types strictly in the outermost leaf crate and convert manually. When you *do* control both sides (internal cluster protocol), skip serialization libraries and send checksummed `extern struct` bytes as-is. | Leaf rule: prevents IPC format lock-in and heavy `serde` proc-macro compile costs from infecting foundation crates. Raw bytes rule: eliminates parsing moving parts when both endpoints ship together. | In 2019 he temporarily forced `serde` into `ra_syntax` to avoid duplicate compilations before reversing it in 2021 ([fork F1](limits.md#forks-and-reversals)); raw struct casting requires explicit cross-platform alignment checks. |
| **Layer-Qualified Imports** `[C]` | Qualify cross-layer types at the use site (`hir::Type`, `ast::Expr`), group imports by crate (`std`, external, internal), and avoid re-exports in application code. | Making architectural layer crossings visible at a glance during code review and preventing two different paths to the same item. | Public library facades where re-exports define the curated surface. |
| **Toolchain Absence Enforcement (`-Dunreachable_pub`, `anyopaque` / `VTable`)** `[C]` | Enforce "A does not know B" with compiler checks: deny `pub` items not reachable from the crate root, or type-erase a subsystem pointer (`anyopaque` or a narrow `VTable`) so the holder cannot call its methods directly. | When two components live in the same compilation unit (such as TigerBeetle's single Zig package) and a crate boundary is not available. | Raw `anyopaque` hid how state evolved and was later refined into an explicit `VTable` interface ([fork F14](limits.md#forks-and-reversals)). |
| **Early Cutoff Shields and Source-Map Pair** `[C]` | In an incremental query engine, place a cheap projection query between volatile syntax inputs (whitespace, byte offsets) and semantic queries, and emit `(PositionIndependentData, SourceMap)` as a pair so semantic queries depend only on the first element. | Compilers and IDEs where editing inside a function body or adding whitespace must not invalidate crate-wide type/name resolution. | Only needed when fine-grained queries are used; coarse per-file stubs or batch `.rmeta` artifacts avoid query tracking altogether ([boundaries-and-systems](boundaries-and-systems.md#incremental-and-compiler-systems)). |

## Build, CI and automation

| Trick (tag) | Move | Signed when | Wrong when / counter-case |
|---|---|---|---|
| **O(1) Build File and Multicall Binaries** `[C]` | Keep `build.zig` / CI config size independent of project size: expose a fixed set of top-level entry points (`run`, `test`, `fuzz`, `deploy`) with filters, and combine helper binaries/fuzzers into a single BusyBox-style executable that dispatches on `argv`. | Avoiding quadratic link times (`binaries × libraries`) and preventing every new fuzzer or script from adding lines to build/CI configs. | Production vs test builds still need separate compilation profiles. |
| **`cargo xtask` / Automation in the Main Language** `[C]` | Write build, release and CI automation as a small program in the project's primary language (`cargo xtask` or `zig build scripts`) rather than shell scripts or YAML plugins. | Removing a second ecosystem (bash/Python/YAML) and making automation cross-platform and refactorable. | **Bootstrap exception:** the initial script that fetches the compiler itself must use whatever the OS has built in (POSIX `sh` / PowerShell). |
| **Read the Lockfile and `stdx` Vendoring** `[C]` | Audit `Cargo.lock` (not just `Cargo.toml`) asking what each transitive dependency solves for the end user; wrap or vendor small upstream/stdlib types into `stdx` when upstream churns or pulls in heavy proc-macros (`syn`, `regex`). | Keeping build times low, insulating from unstable stdlib churn, and reducing supply-chain surface. | Do not roll your own complex domain library when a vetted crate solves a real user problem. |
| **Ratchet (`tidy`)** `[C]` | Enforce repository conventions with a fast test-time `tidy` script scanning git objects; commit the check upfront with an explicit allowlist of current violations before fixing them. | Turning "almost rules" into mechanical habits that cannot regress while allowing incremental cleanup. | Over-zealous mechanical limits (such as splitting a 72-line function to pass a 70-line check) can make individual functions actively worse (`tb 09de971ab`). |
| **Universal Server (Self-Bootstrapping Automation)** `[C]` | Put custom CI/fuzz-fleet runners in the main repository and run them under a tiny loop that does `git fetch`, checks out `main`, rebuilds itself and runs, so merging a PR deploys the automation. | Project-specific continuous fuzzing or benchmark runners on a small fleet where `main` should be the single source of truth. | At larger fleet scale, proper infrastructure-as-code may eventually replace the loop. |
